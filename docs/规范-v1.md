# 《开个律所》规范 v1

沿用《开个影视公司》的整套技术底盘和玩法骨架，换题材、换三条主线、加一个庭审小对抗。
本文只定规范和施工流程，确认后再动代码。

暂定名《开个律所》（和《开个影视公司》《开个游戏公司》成系列）。不满意可以换成《执业》《所长》《第一年律所》。

---

## 0. 定位

- **全能所**：诉讼部 / 公司部（非诉）/ 知产部 / 刑辩部，四个部门各有案件类型、周期和回款方式。部门即"制作管线"。
- **经营为主体，庭审是高光**：日常是阶段推进 + 每周指令 + 抉择事件；只有大案开庭时弹一个 3~5 回合的举证质证小对抗。
- **和《心证》划清界限**：《心证》是逐句盘问的庭审模拟器；这里的庭审是资源出牌，5 分钟内打完，可跳过自动结算。

## 1. 技术底盘（照搬，不许改）

1. 纯静态、无构建、无外部 CDN。GitHub Pages 直接跑，双击本地文件也能跑。
2. 文件结构：
   ```
   index.html        UI 骨架 + 全内联样式
   src/data.js       静态数据表（岗位/部门/案型/客户/设施/对手/开局/排期/目标）
   src/events.js     事件库（最大一块，独立文件）
   src/art.js        美术清单 manifest + 取图函数
   src/trial.js      庭审小对抗（新增，独立文件）
   src/game.js       逻辑与渲染
   src/install.js    装到桌面 + service worker
   assets/scene/*.webp  assets/portrait/*.webp
   ```
   多个 `<script>` 顺序加载，不模块化（保持 file:// 可跑）。
3. 存档 key `law_firm_sim_v1`，`VERSION=1` 起步，`normalize()` 补齐所有字段默认值。
4. 性能预算：首屏 JS < 220KB；图片全部 `loading="lazy" decoding="async"`；资源总量 ≤ 4MB。
5. **无图可玩**：每个图位都有 CSS 降级，`onerror` 退回纯 CSS。图没出完也能随时 push。
6. 移动端优先，760px / 1100px 两个断点，新 UI 先按 390px 宽验。
7. 代码风格：数据表写成可读的多行对象（事件是给人看的），逻辑函数保持影视版的紧凑风格。

## 3. 三条主线

### 3.1 创收（对应票房）
固定收费 / 风险代理 / 计费小时三种回款曲线，差异化明显：

| 方案 | 签约时 | 过程中 | 结案时 | 特点 |
|---|---|---|---|---|
| 固定收费 | 70% | — | 30% | 稳，上限低，结果好坏不加钱 |
| 风险代理 | 10% | — | 标的 × 分成 × 结果系数 | 全胜爆赚，败诉几乎白干 |
| 计费小时 | — | 每周 × 人数 × 小时费率 | 结算尾款 | 现金流最平滑，但账单会拉低客户满意度 |

### 3.2 声誉（对应口碑）
沿用影视的三字段，语义换掉：
- `prestige` 行业声望 —— 同行、法官、榜单认可，影响招人和大案案源
- `fame` 社会知名度 —— 影响上门委托的数量和质量
- `buzz` 律所舆情 0~100 —— 影响签约金、客户满意度基线，战略页带走势图

### 3.3 执业红线 risk（新）
0~100，游戏里唯一会**直接杀死**你的数值。

**涨**：事件里的越线选项 +8~20 / 未披露利益冲突 +15 / 垫付诉讼费 +6 / 非律师人员签字 +10 / 向客户承诺结果 +12 / 风险代理接刑案 +20
**降**：每 13 周自然 -3；建成"内部合规风控岗"后所有涨幅 ×0.65；主动合规整改事件 -10（花钱花时间）

| 阈值 | 触发 |
|---|---|
| 40 | 司法局风险提示（只进消息栏） |
| 65 | 被投诉立案事件，可花钱或花声望平息一次 |
| 85 | 停业整顿 4~8 周，期间所有案件冻结、房租照付 |
| 100 | **吊销执照** —— 直接坏结局，存档封存 |

战略页用一条红条 + 走势图显示，永远可见。

## 4. 案件系统

### 4.1 三档规模

| 档 | 周期 | 基础创收 | 需要人数 | 评级上限 |
|---|---|---|---|---|
| 小案 | 8 周 | ¥150,000 | 2 | 7.5 |
| 大案 | 18 周 | ¥800,000 | 3 | 9.2 |
| 长期项目 | 32 周 | ¥2,000,000 | 4 | 9.5 |

### 4.2 部门与案型

| 部门 | 案型 | 备注 |
|---|---|---|
| 诉讼部 | 合同纠纷 / 股权纠纷 / 建工纠纷 / 劳动争议 / 执行异议 | 走庭审对抗 |
| 公司部 | 常年顾问 / 股权融资 / 并购重组 / IPO 辅导 / 合规整改 | 周期长，标的大，不开庭 |
| 知产部 | 商标侵权 / 专利无效 / 著作权 / 商业秘密 | 可诉可非诉 |
| 刑辩部 | 经济犯罪辩护 / 取保候审 / 二审改判 / 家事继承 | 周期短，风险高，社会关注度高 |

### 4.3 四阶段

| 阶段 | 推进靠 | 涨哪个维度 |
|---|---|---|
| 0 接案与方案 | 商务 | 博弈 |
| 1 调查取证 | 尽调 | 事实 |
| 2 论证与主攻（开庭 / 谈判） | 庭辩 | 法理 |
| 3 收尾交付（执行 / 交割 / 归档） | 研究 | 交付 |

### 4.4 每周指令（照搬五选一）

| 指令 | 效果 |
|---|---|
| 加班赶工 | 进度 +35%，本周质量 -30%，体力 -3；**连赶三周出事** |
| 死磕细节 | 本周质量 +30%，进度 -20% |
| 团建安抚 | 全组体力 +6，默契积累加快 |
| 控成本 | 本周人力开支 -35%，质量 -15%，体力 -2 |
| 放手 | 14% 概率撞上意外突破（关键证据 / 对方失误） |

### 4.5 结案评级
四维加权 + 团队默契 + 设施 + 高斯随机。

| 评级 | 判决结果 |
|---|---|
| ≥8.5 | 全部诉讼请求获支持 |
| 7.0~8.5 | 主要诉求获支持 |
| 5.5~7.0 | 部分支持 |
| 4.0~5.5 | 调解结案 |
| <4.0 | 败诉 / 交易终止 |

### 4.6 开庭排期
定档逻辑照搬影视的"未来六个月选档"：

- 11~12 月结案潮：拥挤度高，判决更保守（评级 ×0.94），但媒体关注度高
- 3 月、9 月：窗口宽松，拥挤度低
- 定档后可改期一次，赔付案件成本 8%
- 大案撞上对手所同期大案 → 抢走媒体关注，舆情收益减半

## 5. 庭审小对抗（src/trial.js）

**触发**：大案 / 长期项目走诉讼路径、进入阶段 2 时，一个案子只打一次。小案自动结算。

**结构**：3~5 回合，法官心证条 0~100，起手 50。

**手牌**：从案件四维生成 4~6 张
- 证据牌（强度来自「事实」）：书证 / 证人证言 / 鉴定意见 / 电子数据
- 论证牌（强度来自「法理」）：法条适用 / 类案检索 / 程序异议
- 策略牌（强度来自「博弈」）：庭前调解 / 让步换条件

**克制**：程序异议克证人证言、鉴定意见克类案检索、电子数据克书证……出牌比强度 + 克制加成，心证条移动 ±5~18。

**结果**：

| 心证 | 结案评级修正 |
|---|---|
| ≥70 | +1.2 |
| 50~70 | +0.5 |
| 30~50 | 0 |
| <30 | −1.0 |

**加成**：建成"模拟法庭室"起手多一张牌；★名律师带庭辩特质的，每局可重出一次牌。
**可跳过**：一键"交给出庭律师"，按四维取中位结果自动结算。手机端不强迫打。

### 6.1 六个岗位 + ★名律师

| 岗位 | 主能力 |
|---|---|
| 合伙人 | 商务 |
| 诉讼律师 | 庭辩 |
| 非诉律师 | 尽调 |
| 授薪律师 | 研究 |
| 律师助理 | 尽调 |
| 市场与客户关系 | 商务 |

四项能力：**庭辩 / 研究 / 商务 / 尽调**。

### 6.2 ★名律师四特质（对应影视的四种明星特质）
- **创收王**：参与案件的商业潜力大幅提升
- **学术权威**：更容易上明镜榜，声望加成
- **媒体宠儿**：舆情收益强，但有翻车风险
- **万金油**：结案评级明显提升

### 6.3 合约与人员流动
照搬影视版：主创有合约期，到期前谈续约（涨薪 / 压价 / 分红），谈崩或放任会带着客户流失到对手所；对手所也会来挖人。**律所特有**：走的人可能带走客户关系，这是比影视版更疼的损失。

## 7. 客户 / 案源 / 对手

### 7.1 五类客户资产（对应五类观众）
| 类别 | 偏好 |
|---|---|
| 本地中小企业 | 合同纠纷、劳动争议、常年顾问 |
| 上市公司与投资机构 | 并购、IPO、合规、商业秘密 |
| 个人高净值 | 家事继承、股权纠纷、税务 |
| 政府与国企 | 建工纠纷、合规整改、执行异议 |
| 刑事与家事个人客户 | 刑辩、取保、离婚 |

### 7.2 客户关系与复购（对应 IP 与续集）
- 每个客户带「关系等级」，结案评级高 → 关系涨
- 关系够高解锁：**后续委托**（成本低、信任高、收费上浮 15~30%）
- **常年法律顾问**：订阅式月度现金流，不占案件管线，但占人
- **系列案**：同一批当事人的批量诉讼，周期短、单价低、可批量走

### 7.3 六家竞争律所
会真实抢案源、挖人、抢明镜榜名次、抢同一个开庭窗口。有各自画像（老牌红圈 / 诉讼专精 / 低价走量 / 外所中国办公室 / 新锐精品 / 关系型）。

## 9. 事件库规范

沿用影视版 schema，不改：
```js
{id, tier, phase, mood, weight, cooldown, title, text(c), 
 choices:[{label, cost, note, apply(c), risk}], onSkip(c), cond(c)}
```
新增 `risk` 字段：该选项给执业红线加多少。

| tier | 说明 | 目标条数 |
|---|---|---|
| `case` | 绑在案件，按四阶段分 | ≥40 |
| `firm` | 律所经营 | ≥15 |
| `person` | 人物 | ≥10 |
| `close` | 结案后 | ≥8 |
| 行业新闻 | 只进消息栏，不弹窗 | 30 |

**必须有的链式后果**（多幕，数周后回来找你）：证据来源存疑 → 被对方申请排除；越线收费 → 被投诉；带病出庭 → 人倒下；向客户拍胸脯 → 结果不及预期客户翻脸。

8. **榜单能靠多接烂案刷**。改成只认评级 ≥6 的案子，去掉现金项，同行也会随行业水位成长。

## 附：图片加载加固（v1.3）

线上实测（390px、DPR 3、模拟慢速 3G）发现两个问题。

### 一、首屏白下载了 5 倍的图片数据

片场卡上那行头像只有 32~44px，却在下载 512×640 的原始立绘，冗余 5.33 倍。
首屏 7 张图 151KB，其中 118KB 是这个。

做法：`tools/make-thumbs.py` 从 `assets/portrait/*.webp` 生成 128×160 的缩略图到
`assets/portrait/s/`，小头像取缩略图，事件弹窗里的大立绘仍取原图。

| | 改前 | 改后 |
|---|---|---|
| 首屏图片 | 151KB | 50KB |
| 头像冗余 | 5.33x | 1.33x |
| 缩略图总量 | — | 38KB |

缩略图**必须和原图同比例**（512×640 → 128×160）。第一版脚本先裁了上半身再缩，
把 512×396 压成 0.8 的竖比例，脸会纵向拉长——CSS 那边本来就用
`object-fit:cover` + `object-position:50% 12%` 负责裁剪，这里再裁一次两边就对不上了。

**换了立绘要重跑 `python3 tools/make-thumbs.py`**，忘了的话测试会报
「缩略图不比原图旧」。

### 二、图片加载失败后不会自愈

原来的 `artMiss` 一失败就 `img.remove()` 并给容器打 `.no-art`。

- 总览页每周 `render()` 重建 innerHTML，所以网络抖一下能自愈；
- **但弹窗横幅只渲染一次**（结案报告、结局、排期）。打开那一刻网络抖了，
  图就永久没了，网络恢复也回不来。这正是「长期加载不出来」的那个坑。

做法：失败后延迟 700ms、1800ms 各重试一次（带 `?r=n` 绕开浏览器对失败结果的缓存），
两次都失败才降级。实测：

| 场景 | 行为 |
|---|---|
| 断网时打开结案报告，之后网络恢复 | 3 秒后图自己出来（改前：永久没有） |
| 文件真的不存在（404） | 正好 3 次请求后降级隐藏，不会无限重试 |

另外首屏那张场景图改成 `loading="eager" fetchpriority="high"`，其余保持 lazy。

### 三、assets 检查扩到 12 条

`node tests/game-core.test.mjs`：

| 检查 | 防的是什么 |
|---|---|
| 场景文件名在清单里 | 名字打错，静默不用 |
| 立绘文件名和编号在 `portraitCount` 范围内 | 出了图没改数字，永远取不到 |
| `portraitCount` 声明的文件都存在 | 先改数字后放图，抽到不存在的文件 |
| 场景图 1280×720 / 氛围图 960×540 / 立绘 512×640 | 尺寸不对会被拉伸 |
| 场景图 ≤90KB、立绘 ≤70KB | 首屏预算 |
| 每张立绘都有缩略图、没有孤儿缩略图 | 漏生成或漏清理 |
| 缩略图不比原图旧 | 换了图忘了重跑脚本 |
| 缩略图 128×160、总量 ≤120KB | 比例错了脸会变形 |

这些都不是可有可无的：**美术层是静默降级设计的**，文件名错、尺寸错、数字和文件对不上，
游戏一律不报错，只安静地退回色块或纯 CSS，页面上一个字都不提示。

## 附：收费落地与日常业务（v1.4）

### 问题

第一轮平衡把收费基准一路上调（小案 35 万 / 大案 170 万 / 长期项目 500 万）才让账平掉，
但那是国际所的价。真实的商事诉讼大案二三十万到五十万，劳动争议个案几千到两万，
IPO 法律服务费 150~400 万。数字离谱到一眼假。

单纯砍收费会直接回到最早那个「办案必亏」的坑，因为**成本也是假的**：
隔断间房租写了 5 万一个月，Lv3 授薪律师月薪写了 3.6 万。

还有个结构问题：游戏里 `slots` 只有 1~3 条案线，现实中一个六人所同时手里有十几个案子。
原来「闲置律师」零产出纯负担，玩家的最优解是把人裁到刚好够用——既不真实也不好玩。

### 做法

**一、两边一起落地。**

| | 改前 | 改后 | 现实对照 |
|---|---|---|---|
| 小案基准 | 35 万 | 8 万 | 标的百万级合同纠纷 |
| 大案基准 | 170 万 | 45 万 | 标的千万级商事诉讼 |
| 长期项目基准 | 500 万 | 150 万 | ×2.0 = IPO 300 万 |
| 计费小时 | 2.2 万/人/周 | 5500/人/周 | 小时费率 1500~3000 |
| 房租（三级） | 5 / 12 / 25 万 | 0.8 / 2.8 / 7.5 万 | |
| 工资公式 | `7000+lv*5200+stat*680` | `2200+lv*2600+stat*340` | 助理 1 万、授薪 2 万、合伙人 3 万 |
| 启动资金（大所出走） | 300 万 | 90 万 | 开个小所 20~100 万 |

场地升级费、设施、目标奖励、贷款、外快、事件花费全部同比下调。

**二、新增日常业务收入。**

没进专案组的人每周自动产生零散业务收入。关键是它**不按人头线性叠加**——
零散活是案源封顶的，上限随知名度、声望、场地成长：

```
daily = min( Σ人手产能 , 案源上限 )
案源上限 = (24000 + 知名度×3000 + 声望×1200) × (1 + 场地等级×0.45)
```

撞到上限时界面标「案源已满」，提示玩家再招人没用、得先做名气。

这条不只是为了平账，它修掉了「闲人纯负担」这个设计缺陷，也让律所规模有了真实的天花板。

### 校验

| | 月成本 | 日常业务 | 专案 | 月结余 |
|---|---|---|---|---|
| 六人小所 · 不接案 | 10.3 万 | 12.7 万（案源已满） | — | **2.5 万** |
| 六人小所 · 办一个大案 | 10.1 万 | 6.3 万 | 10 万 | **6.2 万** |
| 十八人大所 · 三条线全开 | 40.6 万 | 20.3 万 | 51.9 万 | **31.6 万**（年创收 867 万） |

躺平饿不死但十年也就够升一级场地；接案的月结余是它的 2.5 倍。激励梯度对了。
十八人所人均年创收 48 万，落在真实区间（大所 60~120 万）偏下——受 `slots` 限制，合理。

### 顺带验证了红线的反馈回路

给模拟器加了第五种打法「看红线」：和「混合」完全一样，只多一条——红线过 55 就收手。

| 打法 | 红线峰值中位 | 吊销率 | 主要结局 |
|---|---|---|---|
| 混合（从不看那根条） | 67 | 23% | 红圈所 22 / 吊销 7 |
| 看红线（过 55 收手） | 64（最高 76） | **0%** | 红圈所 27 |

会看那根条的人永远摸不到 100，而且结果最好。说明红线是个可管理的风险而不是掷骰子，
不需要再调衰减参数。

## 第二期完成情况（v2.0）

### 事件库：27 → 80 条

| tier | 规范目标 | 第一期 | 现在 |
|---|---|---|---|
| `case` 案件（按四阶段分） | ≥40 | 20 | **43** |
| `firm` 律所经营 | ≥15 | 4 | **16** |
| `person` 人物 | ≥10 | 3 | **10** |
| `close` 结案之后 | ≥8 | 0 | **11** |
| 链式后果 | — | 3 | **4** |
| 行业新闻 | 30 | 12 | **30** |

`close` 是新加的 tier：案子结完一到三周才发作的回头账——客户要退费、对家来挖主办、
判决上了新闻、败诉方投诉、当事人说当初没听懂。代码支持在 `processEvents` 开头，
`closeCase` 按规模决定要不要留（小案 18%、大案 35%、长期项目 50%），不是每个案子都有下文。

新增链式后果 `conflict`：没披露的利益冲突，几周后当面被老客户戳破。

### 客户系统

- **老客户回头**：关系 ≥3 且隔了 8 周以上的客户会主动带新委托回来。收费按关系上浮
  （每级 7%），案型挑他这类客户常打的官司，有效期 12 周（老客户愿意等）。案源卡标「老客户回头」。
- **系列案**：批量型案子（合同、劳动、商标、著作权、执行）办到 6.5 分以上，
  35% 概率派生一批同当事人的系列案——周期 ×0.62、收费 ×0.55，一次办完比一个个办省事。
- **常年顾问续签**：合同两年一签。到期续不续看三件事：关系、口碑、**当初那个负责人还在不在所里**
  （人走了只有 35% 能续）。续签有一半概率涨价。战略页显示到期倒计时，13 周内标红。

### 对手行为

六家各有 `bent`，决定它们抢什么案子：

| | 路子 | 盯着抢 |
|---|---|---|
| 恒泰 | 老牌红圈 | 通吃，偏大案 |
| 京衡 | 诉讼专精 | 诉讼部、刑辩部 |
| 汇通 | 低价走量 | 小案 |
| 远东 | 外所办公室 | 公司部（跨境并购） |
| 执一 | 新锐精品 | 只挑收费高的大案 |
| 广源 | 关系型 | 政府国企、上市公司客户 |

每 4 周有一家出手，按自己的路子挑最想要的那条案源。**你的名气越大越抢不走**
（`hold = (声望+知名度) / (对手实力×3)`，封顶 75%）。

**挖人改成有预警的**：每 8 周物色一个薪水低于行情 15% 以上的人，先在消息栏说「XX所在接触某某」，
再过 8 周才动手（60% 成功）。中间这段时间玩家可以在档案页点「加薪」留人。
人被挖走有 50% 概率带走一个老客户的关系。团队页给低薪的人标「低于行情」，被接触的标「被人接触」。

**抢排期改成排期前就看得见**：对手的大案排期是能提前打听到的，排期弹窗里直接标
「恒泰律师事务所的大案也排在这一周，版面要分一半」。撞上了媒体关注 ×0.5，
声誉收益跟着减半——但玩家有机会避开，这才是决策而不是挨刀。

### 事件重复率：验收标准的调整

规范原话是「一局打完不重复看到同一事件三次」。实测下来这个标准定不到，原因是结构性的：

- 十年 520 周约触发 95 条事件，事件池 76 条（可随机抽的）
- 但事件按 tier 和阶段**分池**：`case` 43 条分到四个阶段，每阶段有效池只有十来条，
  而「调查取证」是四阶段里最长的那个，被抽的次数最多
- 按抽卡的数学，95 次抽取落在十来条的池子上，最大重复次数期望就在 3~4

做了两件事把分布压平：

1. **见过的往后排**：`pickEvent` 里每见过一次，权重乘 0.2。池子没榨干之前基本不重复。
2. **触发率按「期望触发次数 ≈ 池子大小」重配**：case .26→.12、firm .10→.04、person .08→.025，
   close 按案件规模决定要不要有。整体从每 3.8 周一条降到每 5.5 周一条。
   **改事件数量的话这三个数要跟着动。**

最终验收标准改成三条（`tests/game-core.test.mjs` 里，跑 10 次全绿）：

- 随机事件不会被刷到第五次（≤4）
- 撞见三次的事件不超过两成
- 八成以上的事件一局只见一两次

链式后果不算在内——那是玩家自己反复选同一类险招招来的，重复本身就是反馈。

### 顺带修掉的测试盲区

原来的长跑测试里没人处理弹出的事件，`curEvent` 一直挂着，`processEvents` 直接返回——
**第一条事件之后整局再没触发过任何事件**，260 周的长跑其实完全没测到事件系统。
现在测试会随机做选择或跳过，并统计每条事件的触发次数。长度也从 260 周拉到完整的 520 周。

### 红线衰减跟着密度调

事件密度降了 37%，越线的机会同比例减少，红线的张力跟着没了（混合打法峰值从 67 掉到 35、吊销 0%）。
衰减从 9 周 -4 改成 11 周 -3。调完：

| 打法 | 红线峰值中位 | 最高 | 吊销率 |
|---|---|---|---|
| 混合（偶尔越线） | 40 | 92 | 0% |
| 看红线（过 55 收手） | 60 | 71 | 0% |
| 激进（永远踩线） | 100 | 100 | **92%** |

丢执照这个结局仍然够得着（激进打法 92%），但不会落在正常玩法头上。

心证落档给结案评级修正：≥70 +1.2 / 50–70 +0.5 / 30–50 0 / <30 −1.0。

### 红线中段链路补齐

原来 40/65/85 三档只有消息栏文字，85 档是 18% 概率直接停业，很突然。现在：

### 合约与人员流动

每个人入所就签 2~4 年合约（开局班底的到期时间是错开的）。到期前 12 周来谈续约，三个选项：

- **按他开的价签**：涨到他开的价，续四年
- **压价**：省钱，但有概率当场谈崩走人（成功率看口碑和他的体力）
- **改分红制**：底薪不动，他经手的案子按 4% 分成

放着不管，到期人就走了。团队页和档案页显示合约倒计时和分红比例。

### 顺带修掉一个会冻住游戏的 bug

合约到期让人离所之后，**案组可能变空，而 `processCases` 里 `if(!team.length)return` 会直接跳过
——案子就永远冻在那个阶段，不推进、不结案，却还在不停触发那个阶段的事件**。
第二期之前没有合约到期，所以从没暴露；是事件重复率测试连续失败把它揪出来的
（同一阶段的事件集体刷到 ×5–6，就是有案子卡住的特征）。

现在：每周把离所的人清出案组；案组空了会立刻提示并暂停，四维每周掉 1.5、客户满意度掉 3；
拖满六周客户解约，退回一半已收费用，客户关系 −2。

### 零值陷阱

`S.flags.rectAt && S.week-S.flags.rectAt<8` —— 开局第 0 周做整改时 `rectAt=0`，
`0 &&` 是假值，冷却判断直接失效。这类 `||0` / `&&` 写法在以周计数的字段上要格外小心。

### 验收：红线路线 vs 合规路线

模拟器加了三个只在红线行为上有区别的对照组（各 30 局完整十年）：

| 打法 | 活到终局 | 吊销 | 破产 | 办结 | 终局现金 | 红线峰值中位 | 主要结局 |
|---|---|---|---|---|---|---|---|
| 合规派（从不越线 + 建风控岗 + 定期整改） | 100% | 0% | 0% | 32 | 4461 万 | 5 | 红圈所 11 / 还开着 10 / 精品所 9 |
| 红线管理派（敢越线但会整改） | 80% | 0% | 20% | 27 | 2534 万 | 87 | 精品所 12 / 还开着 9 / 资不抵债 6 |
| 踩线派（永远越线，不整改不建风控岗） | 0% | **100%** | 0% | 3 | 162 万 | 100 | 吊销执照 30 |

两条路线的结果差异极大，这一条达成了。**但有个遗留的设计问题见下。**

### 遗留问题：越线目前没有净收益

「踩线派」十年只办 3 个案子就被吊销——那不是一种打法，是自杀，这符合预期。
问题出在中间那条：**「红线管理派」在每个维度上都不如「合规派」**——
办结少 5 件、现金少一半、评级分布还略差、20% 破产。

原因是越线的收益和成本不对等：

- 收益：越线选项大多给 +6~15 的某一维质量，折算下来约 +0.3~0.6 结案评级
- 成本：越线选项本身多半要花钱（托人 6.5 万、加急 9.5 万、请人走一趟 9 万……），
  事后还要花钱整改（一次约 11 万，八周一次）

结果是玩家学两局就会发现「永远选安全选项」最优，**一半的抉择内容变成死重**。
这不是数值微调能解决的，是「这游戏想说什么」的问题，两个方向：

- **A：就这样**。游戏的态度是「走正道更划算」，越线是陷阱不是诱惑。
- **B：让越线真的诱人**。把越线选项的收益拉高（质量加成翻倍，或直接给钱/给案源），
  让敢越线又会管理的人在速度和评级上明显领先，代价是 20~30% 的出局概率。

这个决定没有对错，取决于要做成什么调性。**已拍板：走 B。见附录 v3.1。**

## 附录 v3.1 · 越线红利：把红线做成可交易的资源

拍板 B 之后的做法。原本的思路是去改那 37 个带越线的选项，一个个把数值拉高——
放弃了，因为文案和数值会各自漂移，以后再加事件还得记住这条规矩。
改成一条系统级规则，写在 `game.js` 的 `shortcutGain()` / `choiceCost()` 里，
所有带 `risk` 的选项自动生效，写新事件的人什么都不用管。

### 规则

省掉的合规流程本身就是收益。一个带 `risk: n` 的选项：

| | 效果 |
|---|---|
| 花费 | 打 82 折（`SHORTCUT_DISCOUNT`），显示价和实扣价是同一个数 |
| 在办案子上 | 当前最短的那一维 **+0.78n**，案件进度 **+1.15n %** |
| 不在案子上（所务 / 人事 / 结案后） | 直接进账 **17000 × n** |

风险越大给得越多。红线由此成为一种可以换东西的资源，而不只是一条惩罚条。
UI 上在选项里多一行琥珀色的「走捷径：交付 +12，进度 +17%」，和红色的「执业红线 +15」
上下贴着，代价和好处在同一屏里对看。

### 配套：限期整改的棘轮

光加收益会让越线变成无脑选项——模拟里一度出现「越线派破产率比合规派还低」的倒挂，
因为安全选项大多要花钱，越线选项反而在贴补现金流。所以同时给 85 档加了记账：

- 每次收到限期整改通知，`S.flags.notices` +1，整改窗口从 6 周缩到 4 周、再缩到 3 周
- 第二次起随通知附行政处罚决定书，罚款 = 月开支 ×1.5（下限 12 万），声望 -2、口碑 -6
- 每挂一次号，风险的自然回落速度就慢一档（每 11 周 -3 → -2 → -1）
- **三年不再出事，最早那次通知从考核口径里划掉**——棘轮能往回扳，但要用三年时间扳

常年顶着 86 过日子的所，会被这套东西一点点磨到动不了；偶尔越一次线、越完就压下去的所，
基本不受影响。这正好是想要的区分。

### 验收：90 局 × 三条只在「碰不碰红线」上有区别的打法

| 打法 | 活到终局 | 现金中位 | 办结 | 承办总件数 | 声望 | 知名度 | 红圈所 |
|---|---|---|---|---|---|---|---|
| 合规派（从不越线） | 96% | 4410 万 | 33 | 2619 | 67.5 | 16.2 | 38% |
| 越线派（风险 <58 才越，绝不逼近通知线） | 98% | 5157 万 | 34 | 2969 | 59.7 | 29.4 | **54%** |
| 红线管理派（风险 <75 就越，长期贴着 86 过） | 97% | 4942 万 | 33 | 2835 | 57.6 | 27.3 | 44% |
| 踩线派（永远越线，不整改不建风控岗） | **0%** | 203 万 | 3 | 118 | 5.6 | 5.5 | 吊销 100% |

读法：

- 越线买到的是**钱、速度、名气、红圈所结局**——现金 +17%、承办件数 +13%、知名度 +81%
- 越线付出的是**声望和口碑**——声望 -8，精品所结局从 31% 掉到 17%
- 两条路都能通关，通向的是不一样的所：一个是案子多、名气大、行业排名第一的红圈所，
  一个是案子精、声望高、圈内口碑好的精品所
- 「不管理」仍然是自杀：十年 3 个案子，100% 吊销

### 一个没解决的问题（记在这里）

三条打法的出局率都在 2~4%，**越线并没有换来更高的失败率**。
原因是模拟器里的机器人能看见风险的准确数值，会在阈值前一步精确收手——
这是完美操盘手的下限，不是真人的。真人会多按一次、会忘记整改、会在案子吃紧的时候
连越三条，然后就滑向「踩线派」那条 100% 吊销的曲线。

也就是说：**危险是真的，只是模拟器测不出来**。没有为了让数字好看去硬塞随机惩罚——
一个把红线管得滴水不漏的玩家被随机吊销，那是不讲理，不是紧张感。
